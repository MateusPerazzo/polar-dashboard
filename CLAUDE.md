## Contexto técnico

- **Sistema:** Windows 11. O dashboard roda localmente e não é hospedado em servidor.
- **Linguagem:** Python.
- **Fonte de dados:** API Polar AccessLink v3. Doc oficial: https://www.polar.com/accesslink-api/

### O que sabemos sobre a AccessLink (a confirmar na documentação)

- O cliente da API é registrado em https://admin.polaraccesslink.com, onde se obtêm `client_id` e `client_secret`.
- A autenticação usa **OAuth2 (authorization code flow)**. Depois de obter o token, é preciso **registrar o usuário** na API antes de acessar os dados.
- Endpoints relevantes para este projeto: sono, Nightly Recharge (HRV), frequência cardíaca contínua e atividade diária (calorias).
- Alguns dados (atividade/exercícios) usam um **modelo de transações**: os dados novos são "consumidos" e, depois do commit, não aparecem de novo. Isso influencia a necessidade de armazenar os dados localmente.

## Estrutura

Dois pacotes: `polar/` (dados: API + banco, sem Streamlit) e `app/` (interface). Imports sempre absolutos a partir da raiz (`from polar import db`, `from app import ui`). Caminhos de `data/` são calculados a partir da raiz (`Path(__file__).resolve().parent.parent`).

- `polar/auth.py`: fluxo OAuth2, rodado uma vez (`python -m polar.auth`); grava `data/token.json`
- `polar/api.py`: chamadas GET à AccessLink com o token
- `polar/db.py`: schema SQLite (`data/polar.db`) e helpers de upsert
- `polar/sync.py`: busca os últimos 28 dias e grava no banco; pode rodar várias vezes (`python -m polar.sync`)
- `scripts/explore.py`: diagnóstico; imprime só a estrutura das respostas
- `tests/`: `unittest` com dados fictícios (`python -m unittest -v`); testam funções puras, sem API nem banco
- `README.md`: instalação e uso, para quem clonar o repositório
- `dashboard.py` (raiz): ponto de entrada do Streamlit; registra as páginas com `st.navigation(..., position="hidden")` (sem menu lateral), injeta o CSS global e, nas páginas de detalhe, desenha a barra do topo (voltar + `ui.top_actions()`); no Resumo, a barra fica no cabeçalho da própria página, ao lado da saudação
- `app/ui.py`: **identidade visual**: cor/ícone de cada grupo (`GROUPS`, os padrões), CSS global, componentes HTML (cabeçalho de página, painel, hero, faixa de estatísticas, pílula, anel, "?"), a barra do topo (`top_actions`: status, engrenagem opcional, Sincronizar), o seletor de período (alinhado à direita) e a aparência (`LIGHT_CSS` para fundo branco e `SOLID_CSS` para quadrados sólidos, injetados por `inject_global_css` conforme a escolha). Novas páginas devem usar estes componentes e as variáveis de cor (`--surface`, `--ink`, `--muted`...), não cores fixas, para funcionar nas duas aparências. As páginas leem cores por `ui.groups()` e `ui.insight_colors()` e mensagens por `ui.levels()`, que aplicam as personalizações; nunca `ui.GROUPS`/`ui.INSIGHT_COLORS`/`insights.LEVELS` direto.
- `app/settings.py`: personalizações em `data/settings.json` (só o que difere do padrão), mescla com os padrões (`apply_colors`, `apply_levels`, funções puras) e imagens dos níveis (`data/recharge/<status>.<ext>` tem prioridade sobre `app/assets/recharge/<status>.png`, via `image_path`) e seu recorte no formato `IMAGE_RATIO` (3:2; `image_crop`, `clamp_crop`, `default_crop`, `fit_crop`, `crop_pixels`), aparência (`look`/`apply_look`) e esquemas em `data/schemes/` (`snapshot`, `with_snapshot`, `scheme_slug`, `save_scheme`, `apply_scheme`, `list_schemes`, `delete_scheme`); sem dependência do Streamlit
- `app/charts.py`: leitura do banco e gráficos plotly no estilo do app (`area`, `bars`, `stacked_bars`, `daily_ticks`, `show`); cores de texto, legenda e grade por aparência em `CHART_COLORS`
- `app/insights.py`: regras do "Insight do dia" (status do Nightly Recharge + HRV vs. média de 7 dias + nota do sono), textos de cada nível (`LEVELS`) e seus limites de tamanho (`TEXT_LIMITS`), tradução dos códigos da Polar e `stage_segments` (hipnograma → trechos); sem dependência do Streamlit, por isso testável
- `.streamlit/config.toml`: tema escuro fixo e toolbar mínima (mudanças exigem reiniciar o Streamlit)
- `app/views/`: uma página por grupo (caminhos nas chamadas `st.Page`/`st.page_link` começam com `app/views/`): `overview.py` (Resumo, com o destaque de cada grupo e links), `sleep.py`, `recovery.py`, `heart_rate.py`, `activity.py`, e `settings.py` (Configurações, em seções recolhíveis: esquemas; aparência; cores dos grupos e do Insight; textos e imagem de cada nível). A pasta não se chama `pages/` para não ativar o modo antigo de multipáginas do Streamlit.

Códigos da API: hipnograma 0=acordado, 1=REM, 2=não-REM mais leve, 3=não-REM leve, 4=profundo, 5=indefinido; `nightly_recharge_status` 1–6 (muito ruim → muito bom); `ans_charge_status` 1–5 (muito abaixo → muito acima do usual).

Rodar sempre com `.\.venv\Scripts\python.exe` (o Python do sistema não está no PATH).
Dashboard: `.\.venv\Scripts\python.exe -m streamlit run dashboard.py`.

Durações do sono (`light_sleep`, `deep_sleep`, `rem_sleep`...) vêm em **segundos**.

## Registro de decisões

- **2026-10-28 · venv + pip:** padrão da linguagem; mais didático que uv.

- **2026-10-28 · Callback OAuth2 com `http.server`:** biblioteca padrão; servidor atende uma única requisição.

- **2026-10-28 · Sincronizar com frequência:** sono, Nightly Recharge e FC só ficam 28 dias na API.
- **2026-10-28 · Dashboard em página única (Streamlit + plotly):** cartões com delta vs. média de 7 dias + 4 gráficos; abas ficam para depois.
